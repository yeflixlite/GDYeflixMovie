1. DESCRIPCIÓN GENERAL DEL PROYECTO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Crea un servidor backend en Node.js + Express que actúe como PROXY INTELIGENTE
de video. El servidor resuelve la URL real de reproducción (HLS m3u8 o MP4)
de múltiples servicios de hosting de video, evitando los errores de CORS que
impiden que el navegador acceda directamente desde una web externa (como la app
YeflixTV).

El sistema tiene estas partes:

  A) BACKEND (Node.js + Express)
     - Servidor HTTP en Express.
     - Desplegado en Vercel (serverless) y también funciona local.
     - Detecta el proveedor de video a partir de la URL de embed.
     - Extrae el enlace real (.m3u8 / .mp4) scrapeando el HTML del embed.
     - Sirve el contenido con los headers CORS correctos para que cualquier
       dominio pueda consumirlo.
     - Reescribe las playlists M3U8 para que todos los segmentos pasen por
       el proxy (evitando bloqueos y errores de CORS en los segmentos).

  B) FRONTEND - Reproductor Interno (public/index.html)
     - Interfaz web premium con diseño dark mode y glassmorphism.
     - Permite pegar una URL de cualquier servicio soportado y reproducirla.
     - Usa HLS.js para reproducir streams HLS en cualquier navegador.
     - Selector de calidad y selector de idioma/audio (cuando hay múltiples).
     - Compatible con PC y dispositivos móviles.

  C) REPRODUCTOR EMBED (controllers/embedController.js → ruta /v?url=...)
     - Página HTML mínima (sin menús ni distracciones).
     - Se usa cuando YeflixTV incrusta el video con un iframe o ventana.
     - Tiene overlay de carga estilo Netflix (logo YEFLIX + spinner rojo).
     - El video comienza a cargar en segundo plano desde el inicio.
     - El overlay se oculta a los 9 segundos.
     - El menú de calidad/audio aparece a los 8 segundos.

  D) SERVICIOS DE EXTRACCIÓN (services/)
     - Un servicio por proveedor de video.
     - Cada servicio es un módulo Node.js que exporta extract(url).
     - extract() devuelve: { videoUrl, type, referer, wrapLevel? }

2. STACK TECNOLÓGICO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - Runtime:       Node.js >= 16.0.0
  - Framework:     Express 4.x
  - HTTP Client:   Axios 1.7.x (con Keep-Alive agents y reintentos)
  - HTML Parser:   Cheerio 1.x
  - CORS:          cors npm package (origin: '*')
  - Compresión:    zlib nativo (gzip para M3U8)
  - Video Player:  HLS.js (CDN jsdelivr, latest)
  - Tipografía:    Google Fonts — Outfit + Inter
  - Deploy:        Vercel (vercel.json configurado) + compatible con Render/Railway
  - Dep. opcionales: puppeteer, puppeteer-extra, puppeteer-extra-plugin-stealth

  IMPORTANTE PARA VERCEL/SERVERLESS:
  - La variable de entorno PROXY_SEGMENTS=false (default) hace que los
    segmentos de video (.ts, .m4s) se sirvan DIRECTAMENTE desde el CDN
    del proveedor (no pasan por Vercel), ahorrando 95% del ancho de banda.
  - Solo los archivos M3U8 (playlist) pasan por el proxy de Vercel.
  - Esto es crucial porque Vercel tiene límite de 10MB por response.

4. RUTAS Y ENDPOINTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  GET /
    → Sirve public/index.html (reproductor web)

  GET /live
    → Sirve public/live.html (reproductor TV en vivo)

  GET /v?url=<embed_url>
    → Sirve el reproductor embed minimalista (para iframes de YeflixTV)
    → Muestra overlay Netflix + logo YEFLIX durante la carga
    → Espera 9 segundos mostrando el overlay mientras el video carga en fondo
    → A los 8 segundos se prepara el menú de calidad/audio
    → El video se muestra al terminar los 9 segundos

  GET /play?url=<embed_url>
    → Detecta el proveedor, extrae el enlace real
    → Para VidHide: descarga y convierte las playlists M3U8 a Data URI
      (necesario porque los CDNs de VidHide bloquean IPs de datacenters)
    → Devuelve JSON: { videoUrl, proxyUrl, type, provider, method }
    → proxyUrl = '/proxy?url=...' (o una 'data:' URI para VidHide)

  GET /proxy?url=<encoded_url>&referer=<encoded_referer>[&forceM3u8=1][&wrapM3u8=720p]
    → Descarga el recurso remoto y lo sirve con CORS headers
    → Para M3U8: reescribe la playlist para que los segmentos pasen por /proxy
      (excepto CDNs en DIRECT_DOMAINS, que se sirven directos para ahorrar banda)
    → Soporta gzip compression en las respuestas
    → Caché en memoria de 8 segundos para playlists M3U8 maestras
    → Timeout: 8s para M3U8, 15s para segmentos de video
    → wrapM3u8: si la playlist es single-level, la envuelve en un master falso
      con la calidad indicada para que el selector de calidad funcione

  GET /extract?url=<embed_url>
    → Igual que /play pero devuelve solo la URL extraída sin proxyUrl
    → Útil para apps externas que manejan su propio proxy

  GET /fetch?url=<any_url>
    → Proxy de HTML ligero para cargar páginas externas
    → Útil para PelisJuanita y otras apps web que necesitan proxiar HTML

5.1  VOE (voe.sx y mirrors)
───────────────────────────────────────────
Mirrors reconocidos: charlestoughrace.com, reitshof.com, v-o-e.com,
  voe-video.com, richardquestionbuilding.com, jenniferperformer.com,
  timmaybealready.com, p-v-o-e.com

Lógica:
  1. Descarga el HTML de la página embed de VOE.
  2. Busca el bloque de configuración del reproductor (jwplayer setup o var voe_config).
  3. Decodifica el JSON ofuscado usando: ROT13 → limpieza de tags → base64 → 
     offset -3 → reverse → base64 → JSON.parse()
  4. Extrae sources[0].file (la URL m3u8).
  5. Si hay múltiples mirrors (VOE_DOMAINS), intenta todos en paralelo (Promise.any)
     y devuelve el primero que responda con éxito.
  6. Los segmentos de VOE tienen CORS abierto, así que se sirven directos
     (sin pasar por el proxy de Vercel).

Caché: 60 minutos en memoria por ID de video.
wrapLevel: VOE devuelve una playlist single-level → usa wrapM3u8 para crear
  el master sintético.

5.2  STREAMWISH / HGCLOUD (y familia)
───────────────────────────────────────────
Mirrors reconocidos: streamwish.com, streamwish.to, embedwish.com,
  wishembed.net, flaswish.com, sfastwish.com, wishfast.top, hgcloud.to,
  hgcloud.net, awish.pro, dwish.pro, cilootv.store, bestx.stream,
  moviesapi.club, hglamioz.com, streamhg.com, niramirus.com, audinifer.com

Lógica:
  1. Normaliza la URL al formato /e/<id> en el mismo dominio.
  2. Descarga el HTML.
  3. Extrae los scripts inline.
  4. Intenta en orden:
     a. Patrón jwplayer().setup({sources:[{file:"..."}]})
     b. Patrón file: "https://...m3u8" o "...master.txt"
     c. Descodifica código eval() con atob o p,a,c,k,e,d unpacker
     d. Patrón sources:[{file:"..."}]
     e. Cualquier URL https que contenga /hls/ o master
  5. El enlace puede ser .m3u8 o .txt (que contiene una playlist HLS válida).
     Si es .txt → forceM3u8=1 en la proxyUrl.
  6. Si el primer intento falla, reintenta con otros dominios de la familia.

Caché: 60 minutos en memoria por ID de video.

───────────────────────────────────────────
5.3  VIDHIDE (y mirrors)
───────────────────────────────────────────
Mirrors reconocidos: vidhide.com, vidhidepro.com, vidhidevip.com,
  vidhideplay.com, ahvide.com, vhid.to, vplay.to, vidhide.net,
  hveembed.com, vsharea.com, minochinos.com, callistanise.com

PROBLEMA ESPECIAL: Los CDNs de VidHide (acek-cdn.com, dramiyos-cdn.com, etc.)
  aplican IP-binding y bloquean peticiones desde datacenters (como Vercel/AWS).
  Algunos CDNs también bloquean CORS en el master.m3u8.
  
SOLUCIÓN IMPLEMENTADA (Data URI Inlining):
  1. El servicio vidhide.js extrae el enlace m3u8 usando scraping paralelo
     sobre todos los mirrors (Promise.any → el más rápido gana).
  2. playController.js detecta que el proveedor es 'vidhide'.
  3. DESDE EL SERVIDOR DE VERCEL (que sí tiene IP no bloqueada en el momento
     de la extracción), descarga el master.m3u8.
  4. Para cada sub-playlist que referencia el master (una por calidad),
     descarga la sub-playlist y reescribe las URLs de los segmentos a absolutas.
  5. Convierte cada sub-playlist a una Data URI base64.
  6. Construye un nuevo master.m3u8 donde las sub-playlists son Data URIs.
  7. Convierte ese master a una Data URI base64.
  8. proxyUrl = la Data URI del master.
  9. El navegador del usuario recibe la Data URI → HLS.js la parsea en memoria
     → los segmentos se descargan directamente desde el CDN (sin proxy).
  10. Los segmentos no están bloqueados por IP porque los descarga el navegador
      del usuario final (IP residencial).

Caché: 60 minutos en memoria por ID de video (a nivel de vidhide.js).

Lógica de scraping en vidhide.js:
  - Intenta todos los mirrors en paralelo (Promise.any).
  - Timeout por mirror: 5 segundos, 1 reintento.
  - Bypass de cookies si detecta "Page is loading" o "Redirecting".
  - Verifica que el HTML contiene 'setup({' o 'eval(function' o 'sources:['.
  - Extrae el enlace usando múltiples patrones regex:
    a. .setup({ sources: [{ file: "..." }] })
    b. file: "https://...m3u8"
    c. file: "https://...master.txt"
    d. file: "https://...playlist.txt"
    e. file: "https://.../hls/..."
    f. atob() decode
    g. p,a,c,k,e,d unpacker
    h. Cualquier URL .m3u8 en el HTML

5.4  FILEMOON (y mirrors)
───────────────────────────────────────────
Mirrors reconocidos: filemoon.sx, filemoon.com, filemoon.to,
  filemooon.com, moonplayer.net, bysejikuar.com, bysesukior.com,
  398fitus.com

Filemoon usa un sistema de seguridad MUY avanzado (doble capa):

ESTRATEGIA 1 - API AES-GCM con ECDSA (para mirrors modernos):
  1. GET /api/videos/<id>/embed/details → obtiene la URL del iframe dinámico.
  2. GET <iframe_origin>/api/videos/<id>/embed/settings → registra la sesión.
  3. POST <iframe_origin>/api/videos/<id>/embed/captcha → inicia Captcha PoW.
  4. Resuelve el Proof-of-Work usando el algoritmo Blake2-custom (implementado
     en JS puro sin dependencias externas).
  5. POST <iframe_origin>/api/videos/<id>/embed/captcha/verify → obtiene token.
  6. POST <iframe_origin>/api/videos/access/challenge → obtiene nonce ECDSA.
  7. Genera un par de claves ECDSA P-256 con crypto.generateKeyPairSync().
  8. Firma el nonce con la clave privada (SHA256 + ieee-p1363 encoding).
  9. POST <iframe_origin>/api/videos/access/attest → obtiene token de acceso.
  10. POST <iframe_origin>/api/videos/<id>/embed/playback → obtiene payload cifrado.
  11. Descifra el payload con AES-256-GCM usando las key_parts filtradas por versión.
  12. Extrae sources[0].url (la URL m3u8).

ESTRATEGIA 2 - Scraping HTML (fallback para mirrors más viejos):
  1. Descarga el HTML del embed.
  2. Busca file: "https://...m3u8" en los scripts.
  3. Fallback a file: "https://...mp4".

7. PROXY CONTROLLER (controllers/proxyController.js) — LÓGICA DETALLADA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Variables de entorno:
  PROXY_SEGMENTS=true|false   (default: false)
    false → los segmentos de video se sirven directos desde el CDN.
    true  → todos los recursos pasan por el proxy (útil para CDNs con CORS bloqueado).

DIRECT_DOMAINS (lista de dominios que permiten carga directa):
  voe, timmaybealready.com, charlestoughrace.com, reitshof.com,
  jenniferperformer.com, vidhide, minochinos, vsharea, callistanise,
  vidhidepro, acek-cdn.com, dramiyos-cdn.com, -cdn.com, .urlset, /hls2/,
  doodstream.com, dood.re, filemoon.sx, googleusercontent.com,
  cloudfront.net, streamwish, swqcdn, sb-cdn, wish, sfastwish, hgcloud, mwish

AD_BLOCKLIST (dominios de anuncios que se bloquean con 404):
  tiktokcdn.com, doubleclick.net, adnxs.com, advertising.com,
  quantserve.com, scorecardresearch.com, clisky.xyz, trbt.it

Proceso del proxyHandler:
  1. Decodifica url y referer de los query params.
  2. Si la URL está en AD_BLOCKLIST → 404.
  3. Determina si es petición M3U8 (por extensión o forceM3u8=1).
  4. Verifica caché en memoria (TTL 8s) para playlists M3U8.
  5. Construye headers HTTP simulando Chrome 124 (usando getMediaHeaders).
  6. Timeout: 8s para M3U8, 15s para segmentos, 20s para otros.
  7. Descarga el recurso con axios (responseType: 'stream').
  8. Si es M3U8: reescribe la playlist con rewriteM3u8():
     a. Convierte URLs relativas a absolutas conservando query params de auth.
     b. Si el segmento está en un DIRECT_DOMAIN → devuelve URL directa.
     c. Si no → lo envuelve en /proxy?url=...
     d. Reescribe atributos URI (keys de cifrado, audio).
     e. Normaliza/arregla atributos #EXT-X-STREAM-INF (RESOLUTION, NAME).
  9. wrapM3u8: Si se especifica wrapM3u8=720p y la playlist es single-level
     (tiene #EXTINF pero no #EXT-X-STREAM-INF), la envuelve en un master
     sintético con el nombre de calidad indicado.
  10. Responde con gzip si el cliente lo soporta.
  11. Si es binario (segmento) → pipe() directo al response.

Resolución de URLs relativas (resolveUrl):
  - Preserva protocolo del origen.
  - Mantiene los query params de autenticación (t=, s=, e=, token=).
  - Soporta rutas absolutas (/path), relativas (../path) y protocolo-relativas.

8. PLAY CONTROLLER (controllers/playController.js)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Parámetros:
    url   = URL del embed del video
    mode  = 'auto' (default) | 'http' | 'puppeteer'

  Flujo modo AUTO:
    1. detectProvider(url) → string del proveedor.
    2. Intenta servicio HTTP dedicado (service.extract(url)).
    3. Si falla (excepción) y el proveedor no es 'doodstream':
       intenta puppeteerExtractor.extract(url) como fallback.
    4. Si Puppeteer no está disponible (require falla) → error claro.
    5. Construye proxyUrl = '/proxy?url=...&referer=...[&forceM3u8=1][&wrapM3u8=...]'

  CASO ESPECIAL VIDHIDE:
    Si provider === 'vidhide':
    - Intentar descargar el master.m3u8 extraído DESDE el servidor de Vercel.
    - Si tiene éxito:
      * Para cada sub-playlist en el master:
        - Descarga la sub-playlist.
        - Reescribe los segmentos a URLs absolutas.
        - Codifica como Data URI base64.
      * Construye nuevo master con las sub-playlists como Data URIs.
      * Codifica el master como Data URI base64.
      * proxyUrl = esa Data URI.
    - Si falla (timeout, 504, etc.):
      * Usa proxyUrl normal como fallback (probablemente fallará también,
        pero al menos el cliente recibe un error claro).

  Respuesta JSON:
    {
      videoUrl: string,   ← URL real del video (sin proxy)
      proxyUrl: string,   ← URL proxiada para el reproductor (o Data URI)
      type: 'm3u8'|'mp4', ← Tipo de contenido
      provider: string,   ← Proveedor detectado
      method: string      ← 'http' o 'puppeteer'
    }

13. PROBLEMAS CONOCIDOS Y SOLUCIONES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEMA: VidHide da error CORS o 504 en el master.m3u8
  CAUSA: Los CDNs de VidHide hacen IP-binding. Vercel usa IPs de AWS que están
         en listas negras de estos CDNs.
  SOLUCIÓN: El playController.js descarga y convierte las playlists a Data URI
            durante la extracción (cuando el servidor aún puede acceder).
            Los segmentos de video los descarga directamente el navegador del usuario
            (IP residencial → no bloqueada).

PROBLEMA: Vidhide carga muy lento comparado con VOE
  CAUSA: El sistema de mirrors de VidHide (minochinos, callistanise, etc.) puede
         tener latencias variables. El proceso de Data URI inlining añade latencia.
  SOLUCIÓN: Promise.any() en el scraping para tomar el mirror más rápido.
            Caché de 60 minutos para no re-extraer el mismo video.

PROBLEMA: Error "No 'Access-Control-Allow-Origin'" en segmentos
  CAUSA: Algunos CDNs bloquean CORS en los segmentos .ts también.
  SOLUCIÓN: Eliminar ese CDN de DIRECT_DOMAINS y dejar que pase por /proxy.
            Para NUpload: asegurarse de que sus CDNs NO están en DIRECT_DOMAINS.

PROBLEMA: En móvil (celular) un servicio carga lento o da error
  CAUSA: Los CDNs del servicio aplican diferentes reglas según la IP.
         En móvil con datos el ISP puede dar una IP diferente.
         HLS.js tiene configuración diferente según el dispositivo.
  SOLUCIÓN: Usar buffering más agresivo en móvil. En la página web, detectar
            si es móvil y ajustar maxBufferLength, etc.

PROBLEMA: Safari iOS no reproduce HLS.js / data: URIs
  CAUSA: Safari no soporta HLS.js para Data URIs en algunos contextos.
         HLS nativo de Safari sí funciona con URLs directas.
  SOLUCIÓN IMPLEMENTADA: 
    - Detectar Safari con: !Hls.isSupported() → usar video.src directamente.
    - Para VidHide en Safari: la proxyUrl debe ser la URL directa del m3u8
      (si el CORS lo permite) o la Data URI (funciona si el m3u8 no es muy grande).
    - Agregar crossorigin="anonymous" al elemento <video>.
    - El atributo playsinline es CRÍTICO en iOS (evita pantalla completa forzada).

PROBLEMA: En móvil el reproductor abre en modo "escritorio" para funcionar
  CAUSA: Algunos servicios bloquean mobile User-Agents.
  SOLUCIÓN: El servidor siempre usa User-Agent de escritorio (Chrome 124 Windows)
            independientemente del dispositivo del usuario. El usuario no necesita
            activar "modo escritorio" en Chrome móvil.

PROBLEMA: Selector de calidad no aparece
  CAUSA: menuWaitPromise no se resuelve correctamente, o HLS.js no dispara
         MANIFEST_PARSED (puede pasar con Data URIs en algunos browsers).
  SOLUCIÓN: Agregar timeout de respaldo:
    setTimeout(() => {
      if (hlsInstance && menu.style.display === 'none') {
        menu.style.display = 'flex';
      }
    }, 10000); // mostrar después de 10s máximo

PROBLEMA: Filemoon no extrae (API ECDSA falla)
  CAUSA: Filemoon actualiza regularmente su sistema anti-bot.
  SOLUCIÓN: El servicio tiene dos estrategias (API + Scraping HTML).
            Actualizar filterKeyParts() según la nueva versión del API.

PROBLEMA: VOE da 404 en el master.m3u8
  CAUSA: Los tokens de VOE (t=, s=, e=) expiran.
  SOLUCIÓN: El caché de extracción es de 60 min. Si el token expira antes,
            se necesita re-extraer. Reducir el TTL del caché a 30 min.

15. EJEMPLO DE FLUJO COMPLETO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Ejemplo: YeflixTV quiere reproducir un video de VidHide en un iframe.

  URL del embed de YeflixTV:
    https://gdyeflix.vercel.app/v?url=https%3A%2F%2Fcallistanise.com%2Fv%2Fymlid5m6q6n3

  Paso 1 — El iframe carga el embed:
    GET https://gd-yeflix.vercel.app/v?url=https%3A%2F%2F...
    → embedController.js renderiza el HTML del reproductor.
    → El overlay YEFLIX se muestra.
    → init() se ejecuta.

  Paso 2 — Extracción del video:
    fetch('/play?url=https%3A%2F%2Fcallistanise.com%2Fv%2Fymlid5m6q6n3')
    → playController.js detecta proveedor: 'vidhide'
    → vidhide.js hace Promise.any() en todos los mirrors
    → minochinos.com responde primero con el HTML válido
    → Se extrae: videoUrl = 'https://m5QqjwpATPzb.acek-cdn.com/hls2/.../master.m3u8'
    → playController.js intenta descargar el master.m3u8 desde Vercel
    → Si tiene éxito: descarga las 3 sub-playlists (720p, 480p, 360p)
    → Reescribe los segmentos a URLs absolutas en cada sub-playlist
    → Convierte cada sub-playlist a Data URI base64
    → Convierte el master a Data URI base64
    → proxyUrl = 'data:application/vnd.apple.mpegurl;base64,AAAA...'
    → Responde JSON: { videoUrl, proxyUrl: 'data:...', type: 'm3u8', provider: 'vidhide' }

  Paso 3 — Reproducción:
    → startStreaming('data:...', 'm3u8', false)
    → Hls.js carga la Data URI (en memoria, sin petición HTTP)
    → Parsea el master → encuentra 3 calidades como Data URIs
    → Selecciona la mayor calidad disponible
    → Los segmentos (.ts) se descargan directamente desde acek-cdn.com
       (el navegador del usuario los pide directamente, sin pasar por Vercel)
    → El video comienza a buffear en segundo plano

  Paso 4 — A los 9 segundos:
    → El overlay YEFLIX se oculta con fade
    → El video aparece y el usuario lo ve

  Paso 5 — A los 8 segundos (antes de que termine el overlay):
    → menuWaitPromise se resuelve
    → Si MANIFEST_PARSED ya ocurrió: el menú de calidad aparece
    → El usuario puede cambiar entre 720p, 480p, 360p

16. NOTAS IMPORTANTES PARA REPRODUCIR EL PROYECTO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Instalar dependencias: npm install

  2. Correr en desarrollo: npm run dev  (usa nodemon)

  3. Correr en producción: npm start

  4. Para Vercel: vercel deploy
     - Asegurarse de que vercel.json esté presente.
     - Las variables NODE_ENV y PROXY_SEGMENTS se setean en el dashboard.

  5. El archivo vercel.json debe ser:
     {
       "version": 2,
       "builds": [{ "src": "server.js", "use": "@vercel/node" }],
       "routes": [{ "src": "/(.*)", "dest": "server.js" }]
     }

  6. Puppeteer NO funciona en Vercel (por el límite de tamaño del bundle).
     DoodStream por tanto falla en Vercel. Para DoodStream, usar Render o Railway.

  7. Las claves de OAuth de Filemoon/VidHide pueden cambiar. Si un servicio
     falla, revisar el HTML de su embed para entender el nuevo mecanismo.

  8. Los mirrors de cada servicio cambian frecuentemente. Mantener actualizada
     la lista en urlDetector.js y en cada servicio.

  9. HLS.js se carga desde CDN (jsdelivr). Si CDN está bloqueado:
     npm install hls.js y servirlo desde /public.

  10. Para agregar un nuevo proveedor:
      a. Añadir sus dominios a PROVIDERS en urlDetector.js
      b. Crear services/miprovedor.js que exporte extract(url)
      c. Añadir el mapeo en getServiceMap() de playController.js
      d. Añadir sus dominios CDN a DIRECT_DOMAINS en proxyController.js
         (si sus CDNs tienen CORS abierto y no hacen IP-binding)
